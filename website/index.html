AI Tech Consultant

A complete AI-powered consulting workflow that turns scattered product knowledge into fast customer support, smarter inbox responses, and more accurate scoping for client work.

Project architecture
Task 1 Knowledge Brain
Task 2 Inbox Agent
Task 3 Meeting to Scope
Shared API + Review

Business problem

1. Finding product knowledge

Support teams waste time locating answers across help articles, screenshots, and product updates. This causes slow responses, inconsistent answers, and repeated work.

2. Responding to customer emails

Teams read incoming emails, classify intent, pull supporting facts, and draft replies while keeping follow-up context intact. This is slow, expensive, and difficult to scale.

3. Converting meetings into work

Client requests often begin as vague ideas such as “improve search” or “add AI functionality.” The team must clarify requirements, assess feasibility, estimate effort, and prepare a proposal.

Architectural rule

Tasks 2 and 3 must call Task 1 through a stable API. They should not duplicate the internal Knowledge Brain logic. This keeps the system modular, reusable, and easier to extend.

Project tasks

Task 1

Knowledge Brain

  • Ingest help articles and screenshots
  • Parse and normalize content
  • Build chunked retrieval and embeddings
  • Answer with citations and escalation
API-first service
Task 2

Inbox Agent

  • Classify incoming email intent
  • Call the Knowledge Brain API
  • Draft grounded customer replies
  • Record human approval and feedback
Human review required
Task 3

Meeting to Scope

  • Analyze transcripts and requirements
  • Check product feasibility
  • Generate scope, estimates, and proposal
  • Compare follow-up change requests
Approval before sending

Recommended technology flow

Component Primary expectation
Task 1 Python crawler, resumable ingestion, article parsing, image-aware retrieval, citations, API, escalation, daily updates.
Task 2 TypeScript inbox workflow with at least 50 realistic emails, classification, grounded drafting, review, learning loop.
Task 3 Python transcript analysis, feasibility checks, structured requirements, scope generation, estimates, proposal, and change tracking.
Evaluation 20+ test cases per task with measurable quality, cost, latency, reliability, and safety metrics.

Execution plan

Day 1

Build the Knowledge Brain foundation: sitemap inspection, resumable crawl, parsing, retrieval, embeddings, and a working API.

Day 2

Complete Task 1 and start Task 2: image-aware answers, citation flow, email dataset, classification, reply generation, and review.

Day 3

Deliver Task 3: transcript handling, scope design, feasibility checks, estimates, proposal drafting, and follow-up change comparison.

Day 4

Integrate systems, run evaluation, compare models, fix failures, document the repo, and finalize the demo and submission package.

Evaluation framework

Quality
  • Correct answer grounded in source evidence
  • Accurate citations and abstention when the answer is not supported
  • Correct classification, risk handling, and scope interpretation
Cost & speed
  • Per-task model cost
  • Median and tail latency
  • Retry and failure rates
Safety
  • No unsupported refund commitments
  • No unapproved scope or pricing promises
  • Clear reviewer approval and audit trail
Submission
  • README, DESIGN, EVALS, and AI_LOG
  • One-command startup and run instructions
  • Demo video with at least one real failure case

Deliverables and required artifacts

  • README.md: setup, prerequisites, actual commands, and one-command run instructions.
  • DESIGN.md: architecture, business rationale, design decisions, trade-offs, and limitations.
  • EVALS.md: measured quality, cost, latency, and reliability results from real test runs.
  • AI_LOG.md: documented AI assistant prompts, decisions, and examples where AI output was rejected or corrected.
  • Demo video: 10-minute walkthrough demonstrating all three tasks and a failure-case explanation.

Final project checklist

  • Task 1 knowledge service and API are live and usable
  • Task 2 inbox workflow reads from Task 1 instead of duplicating knowledge
  • Task 3 transcript-to-scope workflow creates requirements, estimates, and proposal
  • Follow-up meeting changes are compared against the approved baseline
  • At least 20 evaluation cases are run for each task
  • Project documentation is honest, runnable, and review-ready
